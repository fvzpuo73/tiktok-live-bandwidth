## 一、先把带宽这件事说清楚：官方、最低、实战是三套口径

搜"TikTok直播需要多少带宽"，你会看到 2.5M、5M、10M、50M 一堆数字互相打架。它们其实不矛盾，只是口径不同。

| 口径 | 数值 | 性质 |
| --- | --- | --- |
| TikTok 官方推荐上传速度 | **50Mbps 以上** | 官方帮助页给创作者的理想建议值 |
| TikTok Live Studio 官方最低上传 | **2.5Mbps 以上** | 官方工具的"能跑起来"门槛 |

| 1080P 实际配置 | 尽量 **10Mbps 以上** | 同上 |

一句话解释这三套数字的关系：**50Mbps 是官方希望你达到的理想值，2.5Mbps 是工具能启动的下限，5/10/15Mbps 是第三方按分辨率和帧率给出的实战值。** 官方推荐值远高于最低门槛，实战值落在两者之间，就这么简单。

为什么实战值要留一倍以上余量？因为推流码率不是匀速的，画面剧烈变化时峰值能冲到平均值的 1.5–2 倍。带宽没有缓冲，一冲峰值就丢包，丢包就卡帧。你按 10Mbps 码率推流，线路至少要有 20Mbps 的稳定上行，这不是浪费，是保险。

### 流量要买多少 GB

高清 1080P 大约 **500MB/小时**，标清 720P 大约 **350MB/小时**。一天播 4 小时、一个月播 25 天，1080P 约需 50GB 上行流量。加上回看、互动、养号，一个月 100–200GB 比较稳妥，重度带货 500GB–1TB 也不算夸张。

但这个测算会得出一个反直觉的结论：**对绝大多数主播，流量根本不是瓶颈，带宽和 IP 才是。** 2000GB 月流量按 1080P 算能播 4000 小时，一天播 4 小时能播 1000 天。所以下面选套餐时，别被"流量翻倍"晃到眼睛，先看带宽和 IP 类型。

## 二、为什么你的网络"测速很快，一开播就卡"

### 四个元凶，前三个都指向网络

**上行带宽不够。** 家用宽带的典型特征是下行快、上行慢，100M 下行配 10M 上行甚至更少。TikTok 直播吃的是上传，下行数字再漂亮也没用。

**延迟和丢包。** 直播对这条最敏感。官方建议 RTT 控制在 **200ms 以内，理想 150ms 以内**；丢包率官方容忍 **2% 以下**，但实际想要画面丝滑，最好压到 **0.5% 以内**。普通中转线路跳数多，晚高峰一抖动，画面就开始跳帧。

**IP 不干净。** 这是 TikTok 独有的麻烦。平台对账号所在 IP 的"原生度"很敏感，机房 IP、共享 IP、被反复使用过的 IP，容易触发限流甚至 0 播放。带宽再大，IP 不行，直播一样推不动。这也是为什么业内反复强调"一个 IP 对应一个直播账号"，同一 IP 下登录太多账号，风控会直接找上门。

**设备过载。** 最次要也最好解决：CPU 持续 90% 以上、OBS 提示"编码过载"，降分辨率或换硬件编码就行。

### 普通 VPN 和共享 VPS 为什么救不了直播

挂个梯子听起来是最省事的方案，试过的人都知道不行。普通 VPN 走公共中转节点，节点拥挤时延迟和丢包完全不可控，高峰期 RTT 飙到 300ms 以上是常态。更致命的是出口 IP：VPN 的出口几乎都是机房 IP，而且是无数人反复用过的"脏 IP"，TikTok 一识别就限流。

共享 VPS 便宜，但带宽是几十人共抢的，你开播时隔壁在跑爬虫，你这边照样卡；IP 同样是机房段，原生度差。

真正能撑住直播的线路要同时具备四件事：**带宽独享或可控、延迟低且稳定、出口 IP 干净、路由可优化不绕公共互联网**。IEPL、IPLC 这类专线能把这四件事凑齐，代价是贵——市场行情大致在每月 200 元到 1200 元之间，按流量和带宽分档。这不是本文的主角，但你得知道这个价格坐标，才能判断下面 LisaHost 的方案性价比到底如何。

## 七、线路买完，推流端还有几件事要做

线路解决的是"路上不堵"，推流设置解决的是"车本身不漏油"。两边都调对，才算完整。

**官方给的参考参数（照抄即可）：** 分辨率 **720×1280（竖）或 1280×720（横）**、宽高比 **9:16 或 16:9**、视频码率 **2Mbps**、关键帧 **4 秒**、协议 **RTMP（不支持 HLS）**、音频码率 **128kbps**、音频采样率 **44.1kHz**。官方注明这些是参考值，需按环境和内容调整。

**实战调整：**
- OBS 以**管理员身份运行**，否则 Windows 资源调度优先级不够，编码容易卡。
- 编码器优先 **NVENC（N 卡）或 AMF（A 卡）**，软编 x264 对 CPU 压力大，老机器容易过载。
- 1080P/30fps 推 **4000–6000 Kbps** 就够，超过 8000 Kbps 收益递减还容易丢包。官方那个 2Mbps 是"能跑起来"的参考值，不是画质上限。
- 关键帧按官方写 **4 秒**。网上流传的"官方推荐 2 秒"与官方页面不符，以官方为准。
- 音频按官方 **44.1kHz / 128kbps**。部分主播习惯用 48kHz，那是经验做法，不是官方要求。
- 开启**动态码率**，网络波动时自动降码率保流畅，比硬撑高码率卡死强。
- 开播前测一次上行和丢包：**上行带宽低于目标码率的 2 倍就别开播**，开了也是卡。
- 官方说明 **LIVE Studio 目前仅支持 Windows**，且需在 PC 浏览器登录 TikTok。

**5M 专线能播吗？**
能，但仅限于单台手机 + 普通真人出镜 + 网络环境稳定的场景。5M 是起步配置，不是舒适配置。一旦要 1080P、要多机位、要连麦，5M 的余量立刻见底。

**手机 5M 够，为什么电脑要 10M？**
手机走 TikTok App 直播，平台和手机会根据网络状况自动适配画质码率，推流链路简单。电脑走 LIVE Studio 或 OBS，分辨率、帧率、码率、编码器全由你自己设，1080P/30fps 的实际码率就在 4–6Mbps，加上峰值波动，10Mbps 才是安全线。

**1080P 到底要多少带宽？**
实战 10–20Mbps。官方推荐的 50Mbps 是理想值，不是必需值。你按 20Mbps 配，日常推流很稳；按 50Mbps 配，是给多路推流和极端波动留的余量。

**一个 IP 能登几个账号？**
建议一个 IP 对一个直播账号。同一 IP 下登录账号过多，容易被判定为异常操作，导致限流或封禁。矩阵运营就按账号数配 IP，这是必须付的成本。

**4G、5G 能直播吗？**
官方明确说可以。但移动网络的延迟和丢包波动比固网大得多，适合应急或户外，不适合每天固定时段带货。

**粉丝不到 50 人能开播吗？**
不能。官方条件写得很清楚：18 岁以上 + 粉丝 50 人以上，且注明条件可能不经预告变更。这是账号侧的门槛，跟网络方案无关。

**新加坡线路要中转，会不会很麻烦？**
看你现有的条件。如果你已经有香港或日本的出口，直接接上就行；如果没有，这一段的成本和复杂度要算进总预算里。这也是为什么我说 LisaHost 补的是 IP 这一环，不是全部。
